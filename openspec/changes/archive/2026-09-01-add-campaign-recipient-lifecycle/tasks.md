## 1. Domain and persistence

- [x] 1.1 Add campaign recipient and message-version domain models with lifecycle state transitions. Implemented as `CampaignRecipient` (states: Incorporated → Drafted → Sent/Failed, or Excluded from either non-terminal state) plus `CampaignRecipientStatus`. "Message version" is implemented as a snapshot of the campaign's `EmailTemplateId` at incorporation time (`MessageTemplateId`) rather than a separate version counter — simpler, and it satisfies the same duplicate-prevention and message-immutability goals the design called for without inventing new versioning machinery.
- [x] 1.2 Configure EF Core persistence, uniqueness constraints, indexes, and migration for campaign recipient history. `CampaignRecipients` table with a unique index on (CampaignId, ContactId, MessageTemplateId); `FollowUpTasks` gained a nullable `CampaignRecipientId` FK; `Campaigns` gained follow-up configuration columns (`FollowUpEnabled`/`FollowUpDueDays`/`FollowUpType`), needed so a campaign can actually configure the "campaign-configured post-send follow-up" the spec requires. Migration `AddCampaignRecipients`.
- [x] 1.3 Add relational integration tests for candidate discovery, explicit inclusion, duplicate prevention, and safety revalidation. All four covered end-to-end against real SQLite in `CampaignRecipientEndpointTests` (`ShouldDiscoverIncorporateAndListRecipients`, `ShouldReturnConflictWhenIncorporatingSameContactTwice`, `ShouldExcludeDoNotContactRecipientDuringDraftGeneration`).

## 2. Application and API

- [x] 2.1 Add operations to discover eligible late recipients and explicitly incorporate them into open campaigns. `CampaignRecipientService.DiscoverCandidatesAsync`/`IncorporateAsync`, reusing `ContactGroupService.ListMembersAsync` for candidate matching against the campaign's audience groups.
- [x] 2.2 Add campaign-recipient draft generation and outcome reporting. `GenerateDraftsAsync` reuses `EmailDraftService`'s existing render/skip pipeline via a new `GenerateForContactsAsync` method (extracted from the existing filter-based `GenerateAsync`), so DNC/no-email skip logic is not duplicated.
- [x] 2.3 Integrate recipient lifecycle updates with existing draft approval, send outcome, and follow-up creation flows. Send outcome and follow-up creation are fully integrated (`EmailDraftService.SendApprovedDraftAsync` now marks the linked `CampaignRecipient` sent/failed and creates a campaign-configured follow-up, falling back to the global policy for non-campaign sends). Draft *approval* deliberately does not get its own `CampaignRecipient` status — the recipient stays "Drafted" through the underlying `EmailDraft`'s Draft/NeedsReview/Approved states, which remain visible via the linked draft; duplicating that state machine on the recipient would create two sources of truth for the same review progress.
- [x] 2.4 Add recipient lifecycle endpoints and update OpenAPI contracts. `/api/v1/campaigns/{campaignId}/candidates`, `/recipients`, `/recipients/{contactId}`, `/recipients/generate-drafts`; `docs/api/openapi.v1.yaml` updated (0.17.0 → 0.18.0).
- [x] 2.5 Add application and API tests for lifecycle transitions, failures, and do-not-contact exclusions. `CampaignRecipientServiceTests`, two new campaign-aware tests in `EmailDraftServiceTests` (sent/failed + campaign follow-up creation), and the API tests above.
